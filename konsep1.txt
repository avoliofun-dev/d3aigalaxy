# GALAXY AI AGENT
## Dokumen Konsep Produk — Versi 1.0

**Nama proyek:** Galaxy AI Agent  
**Platform:** Web pribadi dengan ruang antarmuka 3D Galaxy  
**Jenis:** Personal AI Assistant & AI Agent  
**Database:** Supabase  
**AI Engine:** OpenAI API  
**Hosting:** Vercel  

---

# 1. RINGKASAN KONSEP

Galaxy AI Agent adalah asisten AI pribadi yang dikembangkan dari web Profil Lengkap Ruang 3D AI Galaxy.

AI akan hadir sebagai karakter di dalam ruang 3D Galaxy dan dapat diajak berkomunikasi melalui chat. Pada pengembangan selanjutnya, AI juga dapat berkomunikasi melalui suara dan menjalankan tugas tertentu.

Tidak seperti chatbot biasa, Galaxy AI Agent dirancang agar mampu menggunakan riwayat percakapan dan memori jangka panjang untuk memahami konteks pengguna.

### Prinsip utama

1. Semua percakapan dapat disimpan secara permanen.
2. AI dapat mengingat informasi penting dari percakapan sebelumnya.
3. AI dapat melanjutkan pembahasan proyek dari sesi terdahulu.
4. Pengguna dapat melihat dan mengelola memori AI.
5. AI dapat dikembangkan menjadi agent yang menjalankan tugas.
6. Semua data pribadi dilindungi dengan autentikasi dan hak akses.

# 2. VISI DAN TUJUAN

### Visi

Membangun asisten AI pribadi yang menjadi pusat interaksi, pengetahuan, dan pengelolaan pekerjaan digital pengguna.

### Tujuan utama

- Mengubah web 3D Galaxy menjadi ruang interaksi AI.
- Menghadirkan karakter AI yang dapat diajak berdialog.
- Menyimpan seluruh riwayat percakapan.
- Membangun memori jangka panjang.
- Menghubungkan AI dengan berbagai tools.
- Mengembangkan AI menjadi asisten yang dapat menyelesaikan pekerjaan.

# 3. PENGALAMAN PENGGUNA

Contoh interaksi:

**Hari pertama**

Pengguna:
"Aku sedang mengembangkan game Be A Leader."

AI:
"Baik, kita bisa menyimpan proyek Be A Leader sebagai salah satu proyek yang sedang kamu kerjakan."

Sistem menyimpan pesan dan membuat kandidat memori mengenai proyek tersebut.

**Hari berikutnya**

Pengguna:
"Lanjutkan proyek game kemarin."

AI:
"Kita lanjutkan Be A Leader. Aku akan menggunakan konteks pembahasan sebelumnya."

AI mengambil informasi relevan dari database sebelum memberikan jawaban.

### Alur penggunaan

1. Pengguna membuka web Galaxy AI Agent.
2. Pengguna login.
3. Pengguna membuka ruang 3D Galaxy.
4. Pengguna membuka panel chat.
5. Pengguna mengirim pesan.
6. Server menyimpan pesan pengguna.
7. Server mengambil memori dan riwayat relevan.
8. Server mengirim konteks ke model AI.
9. AI menghasilkan jawaban.
10. Server menyimpan jawaban AI.
11. Jawaban ditampilkan di panel chat.

# 4. ARSITEKTUR TEKNOLOGI

| Komponen | Teknologi | Fungsi |
|---|---|---|
| Frontend | HTML, CSS, JavaScript | Antarmuka web |
| 3D Engine | Three.js | Ruang 3D Galaxy |
| Hosting | Vercel | Hosting aplikasi |
| Backend | Vercel Functions | API dan logika server |
| Database | Supabase PostgreSQL | Menyimpan data |
| Authentication | Supabase Auth | Login pengguna |
| AI Engine | OpenAI API | Pemrosesan percakapan |
| Memory Search | PostgreSQL / pgvector | Pencarian memori |
| Automation | n8n | Otomasi pekerjaan |

### Diagram arsitektur

```mermaid
flowchart TD
    A[Pengguna] --> B[Galaxy 3D Web]

    F --> G[Ambil Memori]
```

### Prinsip keamanan

- API key OpenAI hanya disimpan di server.
- Jangan menanam secret key dalam file HTML.
- Gunakan Supabase Row Level Security (RLS).
- Setiap pengguna hanya dapat mengakses data miliknya.
- Semua endpoint harus memvalidasi identitas pengguna.
- Gunakan pembatasan permintaan untuk mencegah penyalahgunaan.

| Kolom | Tipe |

# 6. SISTEM MEMORI AI

Sistem memori menjadi salah satu fitur terpenting Galaxy AI Agent.

Ada empat lapisan utama.

### A. Chat History

Menyimpan seluruh percakapan asli.

Contoh:

- Pertanyaan pengguna.
- Jawaban AI.
- Waktu percakapan.
- Sesi percakapan.

### B. Long-Term Memory

Menyimpan informasi penting yang dapat digunakan kembali.

Contoh:

```text
Nama AI: Galaxy

Informasi proyek:
- Be A Leader
- Cardora
- Ekalaya
- Galaxy AI Agent

Preferensi:
- Menggunakan bahasa Indonesia.
- Menyukai antarmuka 3D.
- Mengembangkan aplikasi berbasis web.

Keputusan:
- Menggunakan Supabase untuk database.
- Menggunakan Vercel untuk hosting.
```

Contoh tersebut hanya ilustrasi struktur memori, bukan data yang harus disimpan tanpa persetujuan.

### C. Active Context

Menyediakan beberapa pesan terbaru dalam percakapan yang sedang berlangsung.

### D. Memory Retrieval

Ketika pengguna mengirim pertanyaan:

1. Backend memvalidasi pengguna.
2. Backend mengambil pesan terbaru.
3. Sistem mencari memori yang relevan.
4. Sistem menggabungkan konteks.
5. Konteks diberikan kepada AI.
6. AI menghasilkan jawaban.
7. Jawaban disimpan ke database.

### Pengelolaan memori

Pengguna dapat:

- Melihat semua memori.
- Mengedit memori.
- Menghapus memori.
- Menonaktifkan memori.
- Melihat sumber percakapan memori.
- Menghapus riwayat percakapan.

AI tidak boleh menyimpan password, token, API key, atau informasi rahasia sebagai memori.

# 7. BACKEND CHAT API

Endpoint utama:

`POST /api/chat`

Alur pemrosesan:

```text
1. Validasi sesi pengguna.
2. Validasi isi pesan.
3. Simpan pesan pengguna.
4. Ambil riwayat percakapan.
5. Cari memori relevan.
6. Susun konteks AI.
7. Kirim permintaan ke OpenAI API.
8. Terima jawaban AI.
9. Simpan jawaban AI.
10. Proses pembaruan memori.
11. Kirim jawaban ke frontend.
```

### Penanganan error

- Jika AI gagal menjawab, pesan pengguna tetap tersimpan.
- Jangan menampilkan jawaban sukses palsu.
- Tampilkan pesan error yang mudah dipahami.
- Hindari pesan ganda ketika pengguna mengirim ulang.
- Jangan membocorkan API key atau informasi internal server.
